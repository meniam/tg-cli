## Goal

Событие удаления, пришедшее без `chat_id`, помечает сообщения как удалённые в базе при любых настройках списков доступа; выгрузка и `message context --local` дают `deleted` для личных чатов и обычных групп.

## Problem and contract

Тип плана: product (исправление дыры в 10.3).

- Для `message.delete` без `chat_id` `handleEvent` всегда ищет чаты по `id` (`ChatsOfMessages`; `id` сообщений вне каналов уникальны в аккаунте, поэтому каждый `id` принадлежит одному чату). Для каждого найденного чата вызывается `MarkMessagesDeleted(чат, id)` (чужие `id` в запросе по чату не совпадают и игнорируются).
- Без списков доступа поведение событий для подписчиков не меняется: форма и время события, поле `chat_id` в нём, дедупликация и курсор остаются как сейчас; меняется только запись в базу.
- При включённых списках остаётся прежнее правило: если хоть один найденный чат закрыт, событие отбрасывается целиком и ничего не помечается; если чатов нет в базе, событие отбрасывается, как сейчас.
- Если ни один `id` в базе не найден (сообщения не сохранялись), ничего не помечается и событие уходит подписчикам как сейчас.
- Ошибка поиска или записи не теряет событие молча: тот же повтор `retryEventWrite` и `storageGap`, что у остальных записей.

## Scope

- В плане: `internal/daemon/events.go`, тесты `internal/daemon`, документы (`FEATURES.md` 10.3 и 10.11.2, `AGENTS.md`, `README.md`, `docs/skill/tg-cli/`, решение в `.agents/decisions/` при необходимости).
- Вне плана: обнаружение удаления без потока (10.11.2 остаётся частично), повторная запись сообщения после удаления (сбрасывает `deleted_at`), каналы.
- Затрагиваются: `internal/daemon`, документы.

## Main invariant

1. Форма событий для подписчиков и порядок их доставки не меняются.
2. При включённых списках закрытый чат невидим: событие, затрагивающее закрытый чат, отбрасывается целиком, как сейчас.
3. Помечаются только сообщения чатов, найденных по `id`; чужие чаты не затрагиваются.
4. `just check` зелёный; тесты не обращаются к Telegram.

## Risks and strategy

- Риск: `id` из удаления личного чата совпадает с `id` в канале. Стратегия: `ChatsOfMessages` уже исключает каналы (`chat_id > -1000000000000`), у каналов приходит `chat_id`.
- Риск: событие с `id` разных чатов. Стратегия: пометка по каждому найденному чату; тест на два чата.
- Риск: изменение влияет на фильтр доступа. Стратегия: ветка с включёнными списками не меняется, тесты `TestDeleteWithoutChatPolicy` и закрытого чата проходят без правок.
