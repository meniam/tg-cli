## Goal

1. Все настройки утилиты лежат в одном файле `~/.config/tg-cli/config.toml`: `home`, `default_profile`, `[files]`, `[behavior]`, `[profiles.<имя>]`.
2. Приоритет везде одинаковый: флаг, переменная окружения, конфиг, значение по умолчанию.
3. Файлы профиля `client`, `device`, `transport`, `proxy` больше не читаются и не пишутся; их значения один раз переносятся в конфиг, `session.json` при этом не трогается.
4. Смена имени файла базы (и других файлов профиля) после первого запуска не создаёт молча пустую базу и не ослабляет списки доступа.

## Problem and contract

### Файл конфига

- Путь: `~/.config/tg-cli/config.toml` (`os.UserHomeDir()` + `.config/tg-cli/config.toml`), одинаково на macOS и Linux. Переопределения пути нет: ни `XDG_CONFIG_HOME`, ни `TG_CLI_CONFIG` (Q8). Тесты подменяют путь через `Deps.ConfigPath`.
- Каталог `~/.config/tg-cli` создаётся с `0700`, файл `0600`. Запись атомарная: временный файл в том же каталоге, `fsync`, `rename`, под `flock` на `~/.config/tg-cli/config.lock`.
- Чтение: нет файла, значит все значения по умолчанию, это не ошибка. Файл, доступный на запись группе или всем (`perm & 0o022`), или неразборчивый TOML, или неизвестный ключ: код 2 до любого действия, текст называет ключ или строку, но не значение `proxy`. Файл, читаемый группой или всеми, при непустом `proxy` с паролем или секретом: предупреждение в stderr.
- Формат (пример, значения по умолчанию закомментированы):

```toml
# home = "~/Library/Application Support/tg-cli"   # по умолчанию os.UserConfigDir()/tg-cli
# default_profile = "default"

[files]
# database  = "store.db"
# session   = "session.json"
# log       = "daemon.log"
# deletions = "deletions.jsonl"
# access    = "access.json"

[behavior]
# throttle_percent = 60
# flood_autowait   = "10s"
# expect_user      = ""

[profiles.default]
client    = "desktop"
device    = "MacBook"
transport = "tcp"
proxy     = "socks5://user:pass@127.0.0.1:1080"
```

### Ключи и приоритет

| Ключ | Флаг | Переменная | Проверка |
| --- | --- | --- | --- |
| `home` | нет | `TG_CLI_HOME` | `~` и `~/...` раскрываются через `os.UserHomeDir`; `~user` ошибка; после раскрытия путь абсолютный, иначе код 2; `filepath.Clean` |
| `default_profile` | `--profile` | нет | regexp профиля `paths.go:18` |
| `files.database`, `files.session`, `files.log`, `files.deletions`, `files.access` | нет | нет | только имя без каталога: `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`, без `..`; все пять разные; не совпадают с `daemon.sock`, `daemon.lock`, `.session-start.lock`, `moderation.jsonl`, `account.jsonl`, с `<database>-wal`, `<database>-shm`, `<log>.1`..`.3` |
| `behavior.throttle_percent` | нет | `TG_CLI_THROTTLE_PERCENT` | число 1..100, те же правила, что в `throttle_config.go:13-27` |
| `behavior.flood_autowait` | нет | `TG_CLI_FLOOD_AUTOWAIT` | строка Go duration `>= 0` |
| `behavior.expect_user` | `--expect-user` | `TG_CLI_EXPECT_USER` | как сегодня, без разбора в CLI |
| `profiles.<p>.client` | `daemon start --client` | нет (`TG_API_ID`/`TG_API_HASH` по-прежнему исключают `--client`) | regexp `presetName` (`daemon_cmd.go:76`) |
| `profiles.<p>.device` | `daemon start --device` | нет | 1..64 символа без управляющих |
| `profiles.<p>.transport` | `daemon start --transport` | нет | `netconf.ParseTransport` |
| `profiles.<p>.proxy` | `daemon start --proxy` | `TG_CLI_PROXY` | `netconf.ParseProxy`; `none` или отсутствие ключа: без прокси |

- `TG_CLI_HOME` из окружения ведёт себя как сегодня (без раскрытия `~`, относительный путь как есть): инвариант совместимости.
- Флаг `--home` не вводится: решение его не требует.
- Переменные окружения остаются и перебивают конфиг; документы называют конфиг основным способом.

### Запись настроек профиля

- Пишут: `daemon start --client|--device|--transport|--proxy` и `session import` (только `client`, только если ключа нет). Каждая запись меняет только `[profiles.<p>]` под `config.lock`, перечитывая файл внутри блокировки.
- Запись только при изменении значения. Сегодня `transport` и `proxy` переписываются на каждом `daemon start`; теперь `daemon start` без флагов и без `TG_CLI_PROXY` конфиг не трогает. Запись меняет только строки ключей нужного `[profiles.<p>]` по позициям из разбора `go-toml/v2/unstable`; комментарии, порядок и остальные таблицы сохраняются байт в байт (Q1). Таблицы нет: она дописывается в конец файла. Ключа нет: строка вставляется после последнего ключа таблицы. Профиль задан не таблицей `[profiles.<p>]`, а точечными ключами или встроенной таблицей: код 2 с просьбой переписать его отдельной таблицей, файл не меняется.
- `TG_CLI_PROXY` сохраняется в конфиг, как сегодня в файл `proxy`: фоновый потомок не получает переменную (`launch_unix.go:46-49`) и читает прокси из конфига. Файл конфига `0600` (Q6).
- Daemon не читает конфиг. CLI передаёт ему готовые `Paths` (с именами из `[files]`) и имя пресета для `session export` в `daemon.Options` вместо чтения `paths.Client` (`internal/daemon/session.go:52`). Фоновый потомок сам читает конфиг (он наследует `HOME`) и получает те же значения; родитель уже проверил их.

### Миграция

- Что переносит: для каждого каталога профиля в действующем `home` (имена по regexp `paths.go:18`) файлы `client`, `device`, `transport`, `proxy` в `[profiles.<имя>]`. `session.json`, `store.db`, `access.json` и журналы не открываются.
- Когда (Q4): автоматически в начале команд, которые читают настройки профиля (`daemon start`, `session export`, `session import`, `tg config show`), и явной командой `tg config migrate`.
- Порядок для одного запуска, всё под `config.lock`:
  1. Найти профили, где есть хотя бы один из четырёх файлов. Нет таких: выход без изменений (идемпотентность).
  2. Прочитать и проверить каждый файл теми же функциями разбора, что для флагов. Пустой или из пробелов файл считается отсутствующим. Неверное значение: код 2 с именем профиля и файла (значение `proxy` не печатается), ничего не меняется.
  3. Сверить с конфигом. Ключа нет: берётся значение файла. Ключ есть и совпадает: файл просто удаляется на шаге 6. Ключ есть и отличается: конфиг главнее, файл не удаляется, предупреждение в stderr с именами профиля и ключа; повторный запуск снова предупредит.
  4. Резервная копия до первой записи: копия только четырёх переносимых файлов (Q3): копия четырёх файлов и текущего `config.toml` в `<home>/.config-migration-<YYYYMMDDTHHMMSS>/<профиль>/`, каталог `0700`, файлы `0600`). Имя с точкой не совпадает с regexp профиля, поэтому `DuplicateProfiles` (`internal/daemon/session_file.go:52-64`) его не сканирует.
  5. Записать конфиг атомарно и перечитать его разбором: значения должны совпасть.
  6. Удалить перенесённые файлы. Сбой между шагами 5 и 6 безопасен: повторный запуск видит совпадающие значения и только удаляет файлы.
- Значения как есть: `transport = "tcp"` из файла пишется явно, `proxy = "none"` не пишется (отсутствие ключа то же самое).
- Откат: остановить Daemon, вернуть файлы из резервной копии в каталог профиля, вернуть `config.toml` из копии (или удалить `[profiles.*]`), поставить прежний бинарь. Прежний бинарь `config.toml` не читает. Настройки, изменённые после миграции, при откате теряются.

### Смена имени файла после первого запуска

Проверка в `daemon start` (родитель и потомок) до `store.Open`, `access.Open` и работы с сессией. Поведение по Q5 (решено):

- `database`: файла нет, а в каталоге профиля есть файл `store.db` или другой обычный файл с заголовком SQLite (`SQLite format 3\x00`, первые 16 байт): код 2, текст называет оба имени и предлагает переименовать файл или вернуть имя в конфиге. Пустую базу Daemon создаёт, только если других баз нет.
- `access`: файла нет, а есть `access.json` (имя по умолчанию): код 2. Без проверки Daemon открыл бы чтение всех чатов: отсутствие файла выключает фильтр (`access.go:151-156`).
- `session`: файла нет, а есть `session.json`: код 2, иначе потребуется новый вход и старая сессия останется лежать секретом без хозяина.
- `deletions`, `log`: файла нет, а есть файл с именем по умолчанию: предупреждение в stderr, запуск продолжается.
- `home`: каталога профиля нет в новом `home`, а в `os.UserConfigDir()/tg-cli/<профиль>` он есть: предупреждение в stderr.

### Сокет

- Имя сокета не настраивается, поэтому предел зависит от `home` и профиля: длина `home` не больше `103 - len("/<профиль>/daemon.sock")`, то есть 83 байта для `default` и 58 для профиля из 32 символов.
- Проверка остаётся в `ResolvePaths`; текст ошибки называет оба способа: `set home in config.toml or TG_CLI_HOME to a shorter directory`.
- `tg config show` проверяет `home` для всех профилей из `[profiles]` и для `default_profile` и падает кодом 2 заранее.

## Scope

- В плане: новый пакет `internal/config` (загрузка, проверка, запись под блокировкой, миграция); `internal/daemon/paths.go` (имена из конфига); `internal/cli` (`client.go`, `network_flags.go`, `throttle_config.go`, `daemon_cmd.go`, `session_cmd.go`, `cli.go`, новый `config_cmd.go`); `internal/daemon/session.go:52`, `session_file.go:68,78`; `cmd/tg-cli/main.go` (проводка); тексты ошибок с `access.json`; `docs/cli/`, `docs/contracts.md`, `docs/skill/tg-cli/`, `README.md`, `FEATURES.md`; блок `config` в `tg schema`; `AGENTS.md` (список импортов `internal/cli`, раздел Running); запись changelog; новая запись решения для строк Decision log с `Confirmed: no`.
- Вне плана: учётные данные в конфиге (отвергнуто решением); настраиваемые `daemon.sock` и `daemon.lock`; имена `moderation.jsonl` и `account.jsonl` в `[files]` (решение их не называет; добавляются в таблицу документации); перенос данных при смене `home`; Windows; флаг `--home`.

## Main invariant

- Без `config.toml` и после миграции поведение каждой команды то же, что сегодня: те же пути, те же значения по умолчанию, те же коды выхода и тексты ошибок, кроме текста ошибки сокета.
- `session.json` не открывается, не копируется и не меняется ни миграцией, ни конфигом; повторный вход не нужен.
- `store.db`, `access.json`, журналы не меняются миграцией.
- Секрет прокси не появляется в stdout, stderr, журнале Daemon и тексте ошибки (как проверяет `TestProxySecretDoesNotReachBackgroundOutputs`).
- `internal/cli` не импортирует `tgclient`, gotd, `store`; `daemon` не читает конфиг.

## Risks and strategy

- Риск: новый бинарь на живом профиле владельца создаёт пустую базу или открывает чтение всех чатов из-за неверного имени. Решение: проверка смены имени до открытия файлов (шаг 5), живая миграция только с согласия владельца (шаг 12).
- Риск: запись конфига теряет комментарии и порядок ключей владельца. Решение (Q1): правятся только строки профиля, запись только при изменении; тест сравнивает файл с комментариями до и после побайтно вне изменённых строк.
- Риск: гонка двух `daemon start` разных профилей при записи конфига. Решение: `flock` на `config.lock`, чтение и запись внутри блокировки.
- Риск: фоновый потомок читает конфиг, изменённый после проверки родителем. Принято: окно меньше секунды, потомок проверяет значения сам и падает кодом 2 в журнал, `daemon start` сообщает ранний выход (`background.go:133`).
- Риск: тесты читают настоящий `~/.config/tg-cli/config.toml` разработчика. Решение: путь конфига идёт через `Deps` (`ConfigPath`), `newEnv` в `internal/cli/cli_test.go:335` подставляет временный каталог и `HOME`; отдельная проверка, что тесты не трогают `$HOME/.config`.
- Риск: прокси с паролем теперь в конфиге, который владелец чаще открывает и копирует. Решение (Q6): файл `0600`, предупреждение при более широких правах, `tg config show` печатает прокси через `Redacted()`.
- Риск: Codex в песочнице не может создавать Unix-сокеты; большая часть тестов `internal/cli` и `internal/daemon` поднимает Daemon. Решение: Codex гоняет пакеты без сокетов, менеджер гоняет полный `just check` (см. Verification).

Ни одна не сохраняет комментарии при разборе в структуру и обратной записи.
- В `go.mod` и кэше модулей TOML нет; `.codex/agents/pathfinder.toml` к коду не относится.
- Профиль владельца: `~/Library/Application Support/tg-cli/default`, `store.db` около 21 МБ (из решения 0017, не перепроверено).
- `docs/cli/overview.md:61-71` не перечисляет `transport`, `proxy`, `moderation.jsonl`, `account.jsonl`; `docs/cli/daemon-and-auth.md:22-23` пишет умолчание `none` для `--proxy` и `--transport`, в коде `""` и фактически `tcp`. Исправляется в шаге 10.
- `TestSocketPathLimitMatchesTheOS` не проверяет отказ на 104 байтах (`daemon_test.go:452-455` только `t.Logf`).
- `TG_CLI_EXPECT_USER` и его приоритет относительно флага не покрыт тестом в `internal/cli`.
- `TG_CLI_PROXY` сегодня записывается в `<profile>/proxy` вместе с паролем или секретом (`network_flags.go:41-43,62`), хотя `AGENTS.md:51` описывает переменную как способ «без секрета в командной строке».
- `session import` создаёт `client` для профиля без `daemon start` (`session_cmd.go:155-170`).
