## Goal

Агент узнаёт возможности утилиты от неё самой (`tg-cli schema`), выбирает поля ответа (`--fields`), формат (`json`, `jsonl`, `toon`, `human`) и громкость вывода (`--quiet`, `--verbose`), а Daemon запускается одной командой в фоне и по желанию останавливается по простою.

## Scope

- В плане:
  - пометки у каждой команды (класс безопасности, признак `dangerous`, тип результата) и тест полноты;
  - `tg-cli version` и `tg-cli schema` (команды, аргументы, флаги, поля ответов, коды выхода, форматы);
  - глобальные флаги `--fields`, `--format json|jsonl|toon|human`, `--human`, `--quiet`, `--verbose`;
  - формат `toon` через `toon-go` с выравниванием полей, общий форматтер `human`;
  - `daemon start` в фоне с журналом и `--foreground`, `--idle-timeout`;
  - журнал запросов Daemon в файл `daemon.log` с ротацией и команда `daemon logs` (шаг 6, отложен до команды владельца);
  - таблица кодов выхода в схеме и в `AGENTS.md`;
  - тесты, `AGENTS.md`, `FEATURES.md` (через `docwriter`).
- Вне плана:
  - `execute` (решено не делать), `subscribe` (план про живой поток);
  - частичный успех пакетных команд (пока нет пакетных команд);
  - автозапуск Daemon, Windows, запись в Telegram.
- Затрагиваются: `internal/{cli,output,exitcode,daemon}`, `go.mod`, `go.sum`, `AGENTS.md`, `FEATURES.md`, `bin/just/`.

## Main invariant

- Формат `json` по умолчанию и формат `jsonl` не меняются: байт в байт те же ответы, коды выхода те же.
- Ни один режим вывода (`--verbose`, `--human`, `toon`, `schema`) не печатает тексты сообщений, названия чатов, имена, телефоны, секреты сверх того, что команда и так возвращает в своём результате.
- Остаются: Daemon единственный владелец сессии и базы, CLI не импортирует `store`, `tgclient` и gotd напрямую, читающий код не вызывает записывающих методов Telegram.
- `schema` работает без Daemon и без сети.
- `just check` зелёный на каждом шаге.

## Risks and strategy

- Риск: схема расходится с командами. Стратегия: схема строится из дерева команд и их пометок, тест не даёт добавить команду без пометок и без типа результата.
- Риск: рефлексия по типам ответов пропускает вложенные структуры, срезы и указатели. Стратегия: тесты на каждый тип результата, сверка со снимком JSON реального ответа.
- Риск: `--fields` прячет данные при опечатке. Стратегия: решено молча пропускать несуществующие пути (необязательные поля не приходят), поля берутся из схемы.
- Риск: TOON меняет смысл данных (выравнивание `null`). Стратегия: тест на кодирование и обратное декодирование `toon-go`, `json` остаётся умолчанием.
- Риск: фоновый процесс не стартует или остаётся зомби. Стратегия: ожидание ответа сокета не дольше 15 секунд, при раннем выходе ошибка с хвостом журнала, `daemon stop` проверяет завершение процесса, тесты на подмене запуска.
- Риск: журнал растёт без границы. Стратегия: журнал ограничивается по размеру (простая обрезка при старте); с шагом 6 запись на каждый запрос заменяет обрезку ротацией.
- Риск: запись на каждый запрос просачивает параметры (телефон из ссылки на чат, текст сообщений). Стратегия: в запись попадают только метод, время, длительность и код итога; тест на секреты, как в тестах входа.
- Риск: `--quiet` скрывает предупреждение о риске пресета. Стратегия: предупреждение остаётся в `schema` и в журнале Daemon, режим `--quiet` не затрагивает ошибки.
