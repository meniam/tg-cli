## Goal

`AGENTS.md` остаётся коротким индексом (до 8 КиБ): что за проект, как работать, где что лежит и ссылки. Все команды консольной утилиты, их флаги, форматы вывода, коды выхода и правила доступа описаны в `docs/cli/` с пояснениями; подробные контракты поведения лежат в `docs/contracts.md`; решения остаются в `.agents/decisions/` по ссылке; README возвращается к витрине и быстрому старту со ссылками на справочник. Справочник не может разойтись с утилитой: тест падает, если у команды из `tg schema` нет раздела.

## Problem and contract

Тип плана: docs (плюс небольшой тест).

- Решение владельца (2026-11-14): переработать `AGENTS.md`, убрать из него решения и все команды утилиты, создать `docs/` со справкой по параметрам консольной утилиты и ссылаться на неё из `AGENTS.md`.
- Язык: `docs/cli/` и `docs/contracts.md` на английском (правило проекта: справка, API и `AGENTS.md` на английском), `docs/skill/` остаётся на русском, `INTENT.md`, `FEATURES.md`, планы и решения на русском.
- Структура `docs/`:
  - `docs/README.md`: оглавление всей документации и кому что читать.
  - `docs/cli/overview.md`: установка и запуск, профили и каталог данных, Daemon, глобальные флаги (`--format`, `--human`, `--quiet`, `--verbose`, `--fields`, `--profile`), форматы вывода, конверт ответа, коды выхода, `tg schema`, безопасность команд (`read`, `local_write`, `account_write`, `dangerous`).
  - `docs/cli/daemon-and-auth.md`: `daemon start|status|stop|logs`, `auth login|status|resend|cancel`.
  - `docs/cli/chats.md`: `chat list|resolve|info|invite-info|members|topics|common|mark-read`, `chat sync start|status|cancel`.
  - `docs/cli/messages-read.md`: `message history|get|pinned|search|context|comments|link|export|watch`.
  - `docs/cli/messages-write.md`: `message send|edit|delete|forward|send-media|react|pin|unpin|poll`, форматирование текста, `--dry-run`, `--yes`.
  - `docs/cli/notes-and-search.md`: `note add|list|delete`, `search`, `version`, `schema`.
  - `docs/cli/access.md`: `access.json` (`allow`, `block`, `write`, `files`), права файла, перечитывание, что видит агент.
  - `docs/contracts.md`: перенос `.agents/rules/project/contracts.md` без потери содержания (подробные контракты поведения).
- Для каждой команды в справочнике: назначение, синтаксис, таблица флагов (имя, тип, значение по умолчанию, описание), класс безопасности, права и условия (список `write`, `files`, вход в аккаунт), пример вызова и пример ответа (без реальных данных), коды выхода и ошибки, ограничения и что не проверено на живом аккаунте, если это названо в `FEATURES.md`.
- `AGENTS.md` после переработки (до 8 КиБ): Intent со ссылками, одна короткая строка «что умеет» со ссылкой на `docs/cli/overview.md`, Layout укороченный (пакеты в одну строку), Running только про `just`-рецепты и ссылки на справочник и контракты, Security (ключевые правила), Documents and language, Git, Not decided одной строкой со ссылкой; раздел «Decisions made» заменён ссылкой на `.agents/decisions/_TOC.md`, раздел «Plans» ссылкой на `.agents/plans/` и одной фразой о правилах планов.
- README: оставить заголовок, описание, зачем нужен, быстрый старт, краткий список возможностей со ссылками на `docs/cli/`, статус и дорожную карту, структуру проекта в несколько строк; подробные разделы по возможностям (отправка медиа, форматирование, участники и так далее) переносятся в `docs/cli/` без потери содержания; цель до 20 КиБ.
- Тест `internal/cli`: каждая команда из `tg schema` (кроме скрытых) должна иметь в `docs/cli/` заголовок `## tg <путь команды>` или `### tg <путь команды>`; каждый глобальный флаг назван в `docs/cli/overview.md`; относительные ссылки Markdown в `AGENTS.md`, `README.md` и `docs/` ведут на существующие файлы.

## Scope

- В плане: `AGENTS.md`, `README.md`, новый `docs/` (кроме `docs/skill/`, его правит только ссылка на справочник), перенос `contracts.md`, тест полноты справочника и ссылок, обновление ссылок в `.agents/rules/project/AGENTS.md`, `.agents/rules/AGENTS.md`, `FEATURES.md`, `INTENT.md`, решениях, если они ссылаются на перенесённые разделы.
- Вне плана: изменение кода утилиты (кроме теста), перевод `docs/skill/`, правка `INTENT.md` и `FEATURES.md` по существу, правки решений кроме исправления ссылок, правка поведения хранения исходной разметки в базе (отдельная небольшая задача после этого плана).
- Затрагиваются: `AGENTS.md`, `README.md`, `docs/`, `.agents/rules/project/`, `internal/cli` (тест).

## Main invariant

1. Ни одно утверждение справочника не противоречит коду: каждый флаг, значение по умолчанию, код выхода и предел сверены с `--help`, `tg schema` и исходниками.
2. Из README, `AGENTS.md` и `contracts.md` не теряется ни один факт: перенесённое лежит в `docs/` (проверяется сверкой списка заголовков и абзацев до и после).
3. `AGENTS.md` не длиннее 8 КиБ и не содержит списка команд с флагами и списка решений.
4. Тест полноты зелёный; `just check` зелёный.
5. Документы пишет `docwriter` и проверяет независимый `glavred` (правило проекта).

## Risks and strategy

- Риск: при переносе теряются факты. Стратегия: инвентаризация (таблица «что где было и где теперь») до правок, сверка после.
- Риск: справочник описывает не то, что делает утилита. Стратегия: каждый раздел сверяется с `--help` и `tg schema`, примеры ответов берутся из тестов или живой утилиты на пустом профиле, тест полноты.
- Риск: сломанные ссылки после переноса. Стратегия: тест ссылок, поиск `contracts.md` и перенесённых разделов по репозиторию.
- Риск: README после сжатия теряет детали. Стратегия: подробности переезжают в справочник, README ссылается.
