## Goal

Агент читает участников группы, супергруппы или канала (с поиском, смещением и фильтром по ролям), список топиков форума и общие чаты с пользователем; закрытые чаты остаются невидимыми, а увиденные люди и чаты попадают в локальную базу.

## Problem and contract

Тип плана: product (три новые команды чтения).

- Решения владельца (2026-11-14): у списка участников фильтры `--search`, `--offset` и `--filter recent|admins|bots`; полученных людей сохраняем в таблицу `people`; команды называются `chat members`, `chat topics`, `chat common`.
- `tg chat members <чат> [--search ТЕКСТ] [--offset N] [--limit N] [--filter recent|admins|bots]`:
  - Работает для групп, супергрупп и каналов (канал: только если аккаунт админ, иначе ошибка Telegram как код 5 с понятным текстом). Личный чат и бот: код 2 с пояснением.
  - Поля участника: `id`, `name`, `username`, `is_bot`, `role` (`creator`, `admin`, `member`, `restricted`, `banned`, `left`; точный набор уточняет шаг 1), `joined` (время вступления, когда Telegram его даёт). Телефонов и био нет. Имена и username помечены `untrusted`.
  - `--limit` от 1 до 200, по умолчанию 50 (предел уточняет шаг 1); `--offset` не меньше 0; ответ содержит `next_offset`, когда есть продолжение. `--search` и `--filter` можно совмещать (решение владельца): `--filter admins|bots` выбирает роль запросом к Telegram, а текст `--search` Daemon применяет к полученной странице (по имени и `username`, без учёта регистра); поэтому при совмещении поиск смотрит только загруженную страницу, и ответ говорит об этом (`next_offset` продолжает просмотр следующей страницы), а в документах это названо ограничением.
  - Обычная группа: список приходит целиком, поэтому поиск, смещение и фильтр применяет Daemon по полученному списку.
- `tg chat topics <чат> [--limit N] [--cursor C]`:
  - Только для чата с признаком форума, иначе код 2 с пояснением. Поля топика: `id`, `title`, `closed`, `pinned`, `hidden`, `unread`, `top_message`, `created` (набор уточняет шаг 1); заголовок помечен `untrusted`. `--limit` от 1 до 100, по умолчанию 50; курсор непрозрачный (по образцу курсора истории), ответ содержит `next_cursor`.
- `tg chat common <пользователь> [--limit N] [--cursor C]`:
  - Пользователь это `@username` или числовой id (положительный); чат или канал вместо пользователя: код 2. Ответ: список `{id, type, title, username}`; новый тип без поля `unread`. `--limit` от 1 до 100, по умолчанию 50; курсор непрозрачный, ответ содержит `next_cursor`.
  - Закрытые чаты (списки `allow` и `block`) из списка убираются; если страница после фильтра пуста, а продолжение есть, Daemon берёт следующую страницу, пока не наберёт хотя бы один результат или не кончатся страницы (не больше десяти запросов за вызов).
- Доступ: `chat members` и `chat topics` для закрытого чата дают `not_found` тем же ответом, что у неизвестного (`requireAllowedChat`); проверка до обращения к Telegram.
- База: люди из `chat members` и пользователь из `chat common` сохраняются в `people` (`id`, имя, `username`, признак бота), чаты из `chat common` в `chats` (`id`, тип, название, `username`); таблицы членства и топиков не вводятся. Ошибка записи в базу не ломает ответ (как у остальных «по пути»).
- Все три команды класс «чтение», `dangerous` нет, форматы `json`, `jsonl`, `toon`, `human`; `--fields` как у других списков.
- Дроссель: запросы идут через общий бакет; повторов сверх существующей политики нет.
- Релиз одним слоем; откат: откат ветки.

## Main invariant

1. Закрытый чат невидим: `chat members` и `chat topics` отвечают `not_found` до обращения к Telegram; `chat common` никогда не возвращает закрытый чат.
2. Команды ничего не пишут в Telegram; локальная запись только людей и чатов, уже видимых агенту.
3. Чужой текст (имена, `username`, названия чатов и топиков) помечен `untrusted` в схеме и обрамляется в `--format human`.
4. Существующие ответы `json` и `jsonl` не меняются.
5. `internal/cli` не импортирует `tgclient`, gotd, `store`.
6. Ни тест, ни проверка по умолчанию не обращаются к живому Telegram; `just check` зелёный на каждом шаге.

## Risks and strategy

- Риск: большая супергруппа на десятки тысяч человек превращается в массовую выгрузку людей. Стратегия: страницы до 200 и `--offset`, без автоматического обхода всего списка; Telegram сам ограничивает глубину поиска.
- Риск: людей из больших списков много, а `people` растёт. Стратегия: пишется только то, что агент запросил (страница); обхода «всё сразу» нет; размер базы описан в документах.
- Риск: канал не отдаёт участников не админам. Стратегия: понятная ошибка с кодом 5 и пояснением, тест на подмене.
- Риск: форум на живом аккаунте может отсутствовать. Стратегия: шаг 1 выясняет; живая проверка топиков проводится на любом форуме, к которому есть доступ, иначе топики остаются «покрыты тестами, не проверены на живом аккаунте», а в плане это записано.
- Риск: `chat common` отдаёт чаты, которых нет в базе. Стратегия: чаты сохраняются; закрытые (`allow` и `block`) отбрасываются до ответа и до записи.
- Риск: обычная группа отдаёт список целиком и фильтр по смещению нестабилен. Стратегия: порядок фиксирован по `id`, поиск и смещение применяет Daemon по полному списку.

## Known facts

- Аудит шага 1 (Codex, 2026-11-14, отчёт `var/agents/plans/20261114_1911_chat_members_topics_common/audit.md`, в git не входит):
  - Участники супергруппы и канала: `channels.getParticipants` с фильтрами `Recent`, `Admins`, `Bots`, `Search{Q}`, ответ `Count`, `Participants`, `Users`; предел `Limit` в генерированном коде не назван, 200 это решение плана, а не факт gotd. Роли: `member`, `creator`, `admin`, `left`; для `ChannelParticipantBanned`: `banned`, если `BannedRights.ViewMessages`, иначе `restricted`; даты нет у `creator` и `left`.
  - Обычная группа: `messages.getFullChat`, участники в `ChatFull.Participants` (возможен `ChatParticipantsForbidden`), список приходит целиком, поэтому порядок по `id`, поиск, смещение и фильтр Daemon применяет сам.
  - Топики: метод называется `messages.getForumTopics` (не `channels.*`) с `Peer`, `Q`, `OffsetDate`, `OffsetID`, `OffsetTopic`, `Limit`; `ForumTopic` даёт `ID`, `Date`, `Title`, `Closed`, `Pinned`, `Hidden`, `TopMessage`, `UnreadCount`.
  - Общие чаты: `messages.getCommonChats` с `InputUser`, `MaxID`, `Limit`; в какой записи идёт `MaxID` (сырой TL или Bot API) по исходникам не доказано, закрепляется тестом.
  - Ошибки: `CHANNEL_PRIVATE`, `CHANNEL_INVALID`, `USER_ID_INVALID` в `notFoundErrors` (код 7); `CHAT_ADMIN_REQUIRED` в списке нет, даёт код 5 (как в плане); код 2 только от локальной проверки.
  - Курсор истории `{v,c,i}` (Bot API id чата, id сообщения) для топиков и общих чатов не подходит: нужны `{v,chat,date,id,topic}` и `{v,user,max_id}` на том же механизме кодирования.
  - Сохранение людей: `daemon.save` не ломает ответ при ошибке базы, `saveChats` пишет user и bot в `people` (`FirstName` из названия, `IsBot`); для участников нужна отдельная best-effort запись.
  - Доступ: `requireAllowedChat` для числового id отклоняет закрытый до Telegram, имя сначала разрешается через Telegram; для пользователя подходит `resolveStoredReference`.
  - `just check` в песочнице Codex падает на сокетах (ограничение среды).

- Люди из авторов сообщений и личных чатов уже сохраняются в `people` (`internal/daemon/persist.go`).
- `chat info` уже возвращает признак форума (`ChatInfo.Forum`).
