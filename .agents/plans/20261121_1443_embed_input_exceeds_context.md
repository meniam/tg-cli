## Context and sources

- Verified by commands (2026-11-21, живой Daemon и копия базы): `tg status` показывает векторный индекс в ошибке `embed: ollama answered HTTP 413`, построено 22 902 из 24 716 фрагментов, каждый запуск каждые 10 минут падает.
- Причина доказана пробой на копии базы: Ollama 0.40.16 отвечает `413 {"error":"the input length exceeds the context length"}`, когда число токенов одного текста больше 8192. Ввод 200 000 повторяющихся символов проходит (мало токенов), а сообщение чата -1001051500113 №8544 (3221 символ, около 2000 символов эмодзи с ZWJ и модификаторами) даёт 413 начиная с префикса в 3019 символов. Параметр `truncate: true` или `false` не меняет ответ.
- Один такой фрагмент ломает всю пачку из 16 текстов, индексатор останавливается на первой же пачке (`embedAll` в `internal/daemon/semantic_index.go`), остальные ~2000 фрагментов не встраиваются.
- Комментарий в `internal/embed/embed.go` («Ollama truncates a longer input instead of failing») неверен для этой версии.

## Goal

Фрагмент, не помещающийся в контекст модели, не останавливает индекс: клиент встраивает остальные тексты пачки и для длинного текста берёт его начало, которое помещается.

## Scope

- In scope: `internal/embed` (обработка 413 «exceeds the context length»: при пачке из нескольких текстов встроить каждый отдельно, для одного текста укорачивать его (например вдвое) до успеха или до минимальной длины), тест с поддельным сервером, исправление комментария, запись в `docs/contracts.md` или `docs/cli/notes-and-search.md` о том, что длинный или плотный фрагмент встраивается по началу.
- Out of scope: смена модели, смена размера фрагмента в `internal/vectors`, изменение настроек.

## Main invariant

Все ошибки Ollama кроме «input length exceeds the context length» ведут себя как раньше (индекс останавливается, статус `error`). Вектор укороченного текста хранится под хэшем полного текста. Текст сообщений не попадает в журналы и ошибки.
