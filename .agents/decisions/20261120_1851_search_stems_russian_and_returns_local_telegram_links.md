# Поиск знает формы слов через Snowball и возвращает ссылки Telegram, построенные локально

## Context

FTS5 с `unicode61` не склеивает формы слов: на базе владельца `доставка` даёт 88 совпадений, `доставки` 193, `доставку` 43. Результат поиска не вёл в Telegram: чтобы открыть сообщение, ссылку надо было строить командой `message link`, которая ходит в Telegram. Функция `chatref.FormatMessageLink` уже строит ссылки по правилам Telegram без сети.

## Decision

- Основы слов считает Snowball (русский и английский, `github.com/kljensen/snowball`), пакет `internal/stem`; числа, имена и прочие токены остаются как есть.
- Миграция `0011_stem_fts.sql`: столбец `messages.stem_text`, внешний FTS5 `messages_stem_fts`, триггеры, основы пишет скалярная функция `tg_stem()` драйвера (она же заполняет старые строки). Точный `messages_fts` остаётся.
- Обычный `tg search` по `messages` сливает точную и стеммированную ноги через RRF; форма ответа прежняя.
- Каждое попадание и каждый фрагмент несёт `link` по правилам Telegram, собранный локально из `chats.type`, `chats.username` и `topic_id`; фрагмент имеет `link` на первое сообщение и `match_link` на лучшее. Личный чат и обычная группа: `link: null` и причина `private_chat` или `basic_group`.

## Why

- Стемминг вместо лемматизации: достаточно для русского и английского, чистый Go, без словарей. Отвергнуто: словарная лемматизация (сложнее и тяжелее), `ILIKE` (опыт `brain-agent`: нет морфологии, нет индекса).
- Точную ногу оставляем: числа, артикулы и имена стемминг может испортить.
- Локальная сборка ссылки: нет запроса к Telegram, работает без сети и без входа.

## Cost

- Миграция `0011` необратима для старых бинарников, нужна копия базы.
- Внешний инструмент, пишущий в базу, упадёт на триггере без функции `tg_stem()`; пишет только демон.
- Стемминг даёт часть ложных совпадений (разные слова с одной основой); их сглаживает RRF с точной ногой.
