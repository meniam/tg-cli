# Сводка по сохранённым чатам это VIEW chats_state и команда chat overview через фильтр доступа

## Context

В `chats` нет muted, архива, закрепления, непрочитанного и числа сообщений: состояние диалога лежит в `dialog_state` одним JSON, сообщения в `messages`. Первый вариант VIEW с оконными функциями на 100 000 сообщений в 500 чатах считался 431 мс.

## Decision

- Миграция 0008 добавляет только `ADD COLUMN` в `chats` (флаги канала, дата создания, `full_synced_at`, `full_error`), индекс `messages_chat_out_idx` и VIEW `chats_state` на коррелированных подзапросах (26-30 мс на том же объёме).
- Команда `chat overview` (класс `read`) читает VIEW через `ChatFilter`, без Telegram: скрытые чаты не видны и не занимают место в лимите.
- Состав папок остаётся явным (`pinned`, `include`, `exclude`), правила папок лежат в `folders.rules` и не вычисляются.

## Why

- Агентам нельзя открывать базу самим, а ручной SQL обходит списки доступа: нужна команда.
- Отвергнуто: добавить поля в `chat state --local`. Он означает состояние диалога из Telegram, смысл ответа поменялся бы.
- Отвергнуто: вычислять папки по правилам. Telegram не отдаёт правила списком чатов, результат был бы неточен.
- Решения принял менеджер по поручению владельца («Решения сам прими, я не разбираюсь»).

## Cost

- VIEW считается на каждый запрос; при росте базы на порядок нужен пересчёт или материализация.
- Миграция применяется к живой базе владельца при первом старте нового Daemon.
