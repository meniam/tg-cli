# CLI-фреймворк cobra

Decided: 2026-11-13
Revised: —

## Context

Нужно дерево команд с флагами и справкой, а по [замыслу](../../INTENT.md)
команды должны самоописываться для агента. Фреймворк не был выбран
([открытые вопросы](_TOC.md)). Состояние по данным `gh api` на 2026-11-13:
`spf13/cobra` v1.10.2 (44775 звёзд, пуш 2026-07-11), `urfave/cli` v3.14.0
(24321 звезда, пуш 2026-11-10), `alecthomas/kong` (3202 звезды, пуш
2026-11-02, у репозитория нет GitHub-релиза `latest`). Ни один не архивирован.

## Decision

- Используем `github.com/spf13/cobra` v1.10.2.
- Корневая команда без автодополнения (`CompletionOptions.DisableDefaultCmd`),
  `SilenceUsage` и `SilenceErrors`: ошибки печатает `output`, а не cobra.
- Любая ошибка cobra (неизвестная команда или флаг) получает код выхода
  `usage` (2).
- Дерево команд (`root.Commands()`) остаётся источником для самоописания
  схемы, оно проектируется отдельным планом.

## Why

- Самый распространённый в Go: на нём `cli/cli`, образец структуры для этого
  проекта, и агенту он знаком.
- Команды, флаги и справка собираются из дерева, которое можно обойти кодом
  для самоописания.
- Отвергнуто: kong. Теги структур дают компактное описание и самоописание
  «из коробки», но проект на 3202 звезды, меньше примеров и привычности.
- Отвергнуто: urfave/cli v3. Подходит, но по возможностям не лучше cobra при
  меньшем распространении в проектах такого вида.
- Отвергнуто: стандартный `flag`. Вложенные команды и справку пришлось бы
  писать самим.

## Cost

- Больше шаблонного кода, чем у kong.
- Зависимость тянет `pflag` и `mousetrap`.
- Если самоописание окажется неудобным на дереве cobra, решение пересматривается
  (kong дал бы схему из тегов).
