# Код лежит в cmd/ и internal/, без src/ и pkg/

## Context

Нужна структура каталогов Go-проекта: один бинарь для Daemon и CLI
([решение про Go](20261113_2050_language_is_go_with_gotd_td.md)), клиенты ходят
к Daemon по [JSON-RPC](20261113_2051_daemon_speaks_json_rpc_over_unix_socket.md),
публичной Go-библиотеки нет. Для сравнения смотрели через `gh api`:
`cli/cli` (`cmd/gh`, `internal/` на 30 пакетов), `iyear/tdl` (`cmd/`, `core/`,
`pkg/`), `jesseduffield/lazygit` (`cmd/`, `pkg/`), `junegunn/fzf` (`main.go` и
`src/`), `charmbracelet/glow` (плоская структура).

## Decision

- Модуль `tg-cli` (рабочий путь, до выбора названия), `go.mod` в корне.
- `cmd/tg-cli/main.go`: только точка входа, без логики.
- Весь код в `internal/`, пакеты по ответственности: `cli`, `daemon`, `rpc`,
  `tgclient`, `store`, `output`, `exitcode`.
- `cli` не импортирует `tgclient` и `store`: он знает только клиентскую часть
  `rpc`. Границу проверяем линтером.
- Новый пакет заводим, когда у него есть своя причина меняться или своя граница
  зависимостей. Каталоги `models/`, `controllers/`, `utils/` не создаём.
- Интерфейсы объявляет потребитель.
- Тесты лежат рядом с кодом, фикстуры в `testdata/`. Тесты с живым Telegram по
  умолчанию не запускаются.
- Служебное (`.github/`, `docs/`, `scripts/`, `.goreleaser.yml`, `justfile`)
  лежит в корне, не внутри кода.

## Why

- `internal/` запрещает импорт снаружи на уровне компилятора. Публичный API у
  нас JSON-RPC, и язык клиента не важен.
- Отвергнуто: `src/` как у `fzf`. Каждый импорт получает лишний сегмент
  `модуль/src/...`, а выгоды нет: корень с `go.mod` уже есть папка исходников.
- Отвергнуто: `pkg/` как у `lazygit` и `tdl`. Он открывает код для импорта, а
  внешних импортёров нет.
- Отвергнуто: плоская структура как у `glow`. У нас Daemon, протокол, хранилище и
  Telegram-клиент, и им нужны границы.
- Отвергнуто: `main.go` в корне. Корень остаётся для `go.mod`, `justfile` и
  документов, второй бинарь добавляется без перестройки.

## Cost

- Если понадобится публичный Go-SDK, клиент `rpc` выносится в публичный пакет.
- Граница `cli` и `tgclient` держится на дисциплине и линтере (`depguard`),
  компилятор сам её не проверяет.
- Путь модуля `tg-cli` временный: после выбора названия меняются модуль и все
  импорты.
