# Полные данные чатов собирает фоновая задача chat full, прогресс лежит в chats

## Decision

- Команды `chat full start [<chat>] [--refresh]`, `chat full status`, `chat full cancel`. Без чата `start` берёт разрешённые фильтром группы, супергруппы и каналы без `full_synced_at`.
- Одна задача за раз, один рабочий, один запрос на чат (`channels.getFullChannel` или `messages.getFullChat`) с фоновой меткой общего дросселя и паузой 2 секунды; `FLOOD_WAIT` даёт `waiting_flood`, ожидание и один повтор; отмена срабатывает после текущего чата.
- Прогресс чата хранится в `chats.full_synced_at` и `chats.full_error`; состояние задачи в памяти Daemon, после перезапуска задача не возобновляется сама, новый `start` пропускает загруженные чаты.
- Задача только читает и не получает прав записи в Telegram.

## Why

- Полный запрос на каждый чат дорогой (около 175 запросов у владельца), поэтому фоновая задача с отменой и прогрессом, как у загрузки истории.
- Отвергнуто: флаг `chat info --all`. Команда висела бы минуты без отмены и прогресса.
- Отвергнуто: встроить в `chat sync`. Две задачи с разными состояниями.
- Отвергнуто: отдельная таблица задач. Прогресса в двух колонках `chats` хватает.
- Решения принял менеджер по поручению владельца.

## Cost

- Новая группа команд с разделами в `docs/cli/`.
- Состояние задачи не переживает перезапуск Daemon; `start` нужно запускать заново.
