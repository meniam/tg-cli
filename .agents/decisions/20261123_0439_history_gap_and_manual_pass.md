# Дыра в истории чата хранится в sync_state и проходится ручным start

## Context

Если догонка достигает предела раньше границы времени, между старой историей и загруженным верхом может остаться пропуск. Чат может уже иметь `complete = 1` или `oldest_id` ниже пропуска, поэтому прежний повторный `start` не проходит его.

## Decision

- Миграция 0014 добавляет в `sync_state` `gap_from` и `gap_to`. На чат хранится одна дыра; новая расширяет её до общего интервала через `MIN(gap_from)` и `MAX(gap_to)`. Поля `gap_from`/`gap_to` есть в `chat sync start|status|cancel`, а `chat overview` читает границы из базы как `history_gap_from`/`history_gap_to`.- `SaveCatchupPage` сохраняет сообщения и людей одной транзакцией, не создаёт `sync_state` и не меняет `oldest_id`, `newest_id`, `complete` и `first_message_date`. `gap_to` равен наименьшему id догонки; `gap_from` равен наибольшему сохранённому id ниже него с датой не новее `last_alive_at`, либо 0. При отсутствии строки отметка создаёт её с пустыми id и `complete = 0`.
- Пока дыра открыта, `SaveHistoryPage` не поднимает `newest_id` выше `gap_from`. Непрерывный проход от `gap_to` или выше до страницы с id не выше `gap_from`, либо до пустой страницы, закрывает дыру в транзакции страницы. `newest_id` поднимается до верха прохода.
- Ручной `chat sync start` сначала проходит дыру от `gap_to` даже при `complete = 1`. Без флагов проходит её целиком; затем завершает полную историю либо продолжает от `oldest_id`. `--since`, `--days` и `--months` ограничивают проход датой, `--messages N` числом сообщений задачи. Если предел достигнут до закрытия, последняя страница одной транзакцией опускает `gap_to`; `gap_from` и `newest_id` остаются прежними.
- У чата без дыры `--messages N` считает все сохранённые сообщения; на проходе дыры и при продолжении той же задачи считает сообщения этой задачи. Если дыра закрыта раньше предела, полный чат заканчивает задачу, а неполный продолжает загрузку. Для даты в продолжении используется дата самого старого сохранённого сообщения.
- У одного чата могут одновременно быть ручная задача и задача догонки: `status <чат>` предпочитает ручную, `cancel <чат>` отменяет обе. Отдельного признака прохода нет: дыра видна по заполненным границам, после закрытия они пусты.
- `export-month` ставит `sync.month_start_covered = false` при пересечении месяца с дырой. Уточнено 2026-11-23: дата `gap_to` не раньше начала месяца и `gap_from` равен 0, неизвестен либо датирован раньше начала следующего месяца. При отсутствии сообщения `gap_to` покрытие определяется консервативно; новых полей манифеста нет.

## Why

- Одной объединённой дыры хватает, чтобы не объявить пропуск закрытым. Отдельная таблица интервалов и учёт нескольких разрывов сложнее при выбранном сценарии.
- Страницы догонки пишутся отдельно от прогресса глубокого обхода: иначе новый `oldest_id` у верха перескочил бы уже сохранённую историю ниже.
- Отвергнута отдельная команда закрытия: `start` уже известен агенту. Отвергнут запрет флагов при дыре: флаги позволяют проходить большой пропуск частями. Отвергнут игнор флагов при проходе: явный предел должен действовать на эту задачу.
- Предел сообщений сохраняет один смысл до конца задачи с дырой, а не переключается на число всех сохранённых после её закрытия. Признак прохода выводится из границ, отдельное поле не нужно.

## Cost

- Объединение дыр может отметить более широкий интервал, чем фактически потерянный. После закрытия `newest_id` поднимается до `gap_to`, а не обязательно до верха догонки; он и раньше отставал от живых событий.
- У `--messages N` два смысла в трёх случаях: без дыры считается объём чата, на проходе и после него объём задачи. При N не кратном размеру страницы загрузка может превысить N меньше чем на страницу.
- Суженная дыра остаётся до последующих ручных запусков. Пока она есть, `complete = 1` само по себе не означает непрерывного покрытия. Миграция делает базу версии 14 недоступной старому бинарнику без отката из копии.
