# Данные профиля лежат в каталоге профиля, ключи приложения берутся из окружения

## Context

Мультиаккаунт закладывается в основу ([решение про Go](20261113_2050_language_is_go_with_gotd_td.md)):
у каждого профиля своя сессия и свой Daemon. Сессия и `api_hash` секретны
([правила безопасности](../../AGENTS.md)). Путь Unix-сокета ограничен длиной
`sun_path`; на этой машине (macOS) путь в 103 байта привязывается, в 109 нет
(проверено тестом `TestSocketPathLimitMatchesTheOS`).

## Decision

- Каталог профиля: `<TG_CLI_HOME>/<профиль>`, если `TG_CLI_HOME` задана, иначе
  `<os.UserConfigDir()>/tg-cli/<профиль>`. Профиль по умолчанию `default`,
  имя `[a-z0-9][a-z0-9_-]{0,31}`.
- В каталоге: `daemon.sock` (0600), `daemon.lock`, `session.json` (0600).
  Сам каталог 0700.
- Блокировка: `flock` (`LOCK_EX|LOCK_NB`) на `daemon.lock`. Второй Daemon на
  профиле отказывается стартовать. Устаревший сокет удаляется после взятия
  блокировки.
- Длина пути сокета не больше 103 байт, иначе Daemon не стартует и просит
  задать `TG_CLI_HOME` короче.
- `api_id` и `api_hash` читаются из переменных окружения `TG_API_ID` и
  `TG_API_HASH`, нигде не печатаются и не пишутся в файлы.

## Why

- Профиль в пути делает мультиаккаунт раскладкой каталогов, без нового кода.
- Переменные окружения не попадают в файлы проекта и в репозиторий.
- `flock` снимается сам при смерти процесса, ручная чистка не нужна.
- Отвергнуто: `api_hash` в файле профиля. Появился бы ещё один секретный файл.
- Отвергнуто: ключи флагами. Они видны в `ps` и истории шелла.

## Cost

- Только платформы с `flock` и Unix-сокетами (`//go:build unix`): список
  платформ в [INTENT.md](../../INTENT.md) ещё не определён.
- Имя каталога `tg-cli` временное: после выбора названия его нужно сменить, а
  существующие профили перенести.
- Переменные окружения видны процессам того же пользователя через `ps eww` на
  некоторых системах; для личной машины принято.
