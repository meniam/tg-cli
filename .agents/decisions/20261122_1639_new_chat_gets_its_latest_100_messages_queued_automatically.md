# Новый чат получает в очередь загрузку 100 последних сообщений сам, а очередь принимает чаты списком

## Decision

- Новый чат: первое живое сообщение (`message.new`), когда в базе нет ни сохранённых сообщений чата, ни строки `sync_state`. `handleEvent` спрашивает `chatIsNew` до сохранения сообщения, после сохранения зовёт `autoSyncNewChat`.
- Настройка `new_chat_sync.messages`, живая, по умолчанию `100`, `0` отключает, не больше 1000. Переменная `TG_CLI_NEW_CHAT_SYNC_MESSAGES`.
- Загрузка идёт задачей с `source: background` и пределом глубины `Messages = N`, через тот же `historySyncManager`, дроссель и паузу между страницами планировщика. `historySyncManager.startAuto` ставит её за уже стоящими, ничего не отменяя и не требуя свободного менеджера. Ручной `start` того же чата заменяет такую задачу.
- Работает только при включённом планировщике (`d.background != nil`, то есть `background_sync.enabled`): выключатель владельца «Daemon не делает собственных запросов за историей» остаётся единым. Закрытый чат не ставится.
- `chat sync queue <чат>...` (до 100 чатов) ставит названные чаты без обхода списка диалогов. Каждый чат проверяется до постановки, закрытый или неизвестный даёт код 7 на весь вызов. Фильтры со списком несовместимы (код 2). Загруженный или стоящий в очереди чат попадает в ответ с `skipped_loaded` или `skipped_active`.

## Why

- Свежий чат без истории бесполезен для поиска и сводок, а сотня сообщений стоит одной страницы запросов.
- Один выключатель с планировщиком: два независимых источника запросов к Telegram за историей дали бы владельцу два места, где их отключать.
- Очередь с глубиной вместо отмены фоновой задачи: загрузка нового чата короткая, а отмена прерывала бы долгую.
- Список в `queue`, а не в `start`: ответ `start` это одна задача, а пачка уже возвращает список с действиями. Агент получает одну команду для любой пачки и не пишет свой цикл.
- Отвергнуто: считать новым чат, которого нет в таблице `chats`. Список диалогов кладёт чаты в таблицу заранее, и такое условие почти никогда не срабатывало бы.
- Отвергнуто: ставить сотню на каждый чат из обновления списка диалогов. После первого запуска это сотни задач сразу.

## Cost

- Чат, давно лежавший в списке диалогов без сохранённых сообщений, получает загрузку 100 сообщений, когда в нём пишут, даже если владелец его не читает.
- Загрузка идёт без отдельного учёта: обычный дроссель аккаунта и пауза планировщика.
- Пока в очереди длинная загрузка, сотня нового чата ждёт её конца (очередь одна на Daemon).
