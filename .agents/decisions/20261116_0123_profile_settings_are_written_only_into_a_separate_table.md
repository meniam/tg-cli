# Настройки профиля пишутся только в отдельную таблицу

## Context

`daemon start` и `session import` меняют отдельные ключи профиля, сохраняя
комментарии и порядок остальных частей `config.toml`. Для этого редактор
заменяет только строку ключа в таблице `[profiles.<имя>]`.

TOML допускает точечные ключи и встроенные таблицы. У них нет отдельного
участка текста, который можно безопасно изменить без перестройки чужой записи.

## Decision

Профиль, который команда должна изменить, задаётся только отдельной таблицей
`[profiles.<имя>]`. Если профиль задан точечными ключами или встроенной
таблицей, запись завершается кодом 2, а файл не меняется.

## Why

Так команды сохраняют комментарии, пустые строки, порядок и чужие таблицы
байт в байт. Альтернатива, переписать файл сериализатором TOML, теряет эти
правки владельца.

## Cost

Владелец должен переписать профиль отдельной таблицей перед первым изменением
настройки командой. Чтение таких форм конфигурации остаётся возможным, пока
значение не нужно менять.
