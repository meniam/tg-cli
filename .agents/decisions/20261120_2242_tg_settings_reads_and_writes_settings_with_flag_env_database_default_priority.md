# Команда tg settings читает и пишет настройки, приоритет флаг, переменная, база, умолчание

## Context

Настройки переезжают в базу профиля
([решение о хранении](20261120_2242_settings_live_in_the_profile_database_and_config_toml_keeps_only_what_finds_it.md)).
Раньше их правил человек в редакторе, а `tg config show` только показывал файл.

## Decision

- Группа команд `tg settings` читает, пишет и сбрасывает настройки профиля,
  выбранного `--profile`. Минимальный набор подкоманд и форму ключей выбирает
  план `20261120_2242_settings_in_database` (там же открытые вопросы); в набор
  входят как минимум `list`, `get`, `set`, `unset`.
- Приоритет прежний: флаг командной строки, переменная окружения, значение в
  базе, значение по умолчанию. Переменные `TG_CLI_*` и флаги, которые есть
  сегодня, остаются.
- Команда, её ключи, типы, умолчания, переменные и флаги видны в `tg schema`.
  Раздел `docs/cli/` пишется вместе с командой: тест `internal/cli` падает без
  раздела.

## Why

- Так решил владелец: одна команда вместо правки файла.
- Отвергнуто: отдельная команда на каждую секцию (`tg throttle set`,
  `tg proxy set`). Много поверхностей ради одной операции «ключ и значение».
- Приоритет не меняется, чтобы не сломать сценарии с переменными окружения.

## Cost

- Новая группа команд в схеме, в справочнике и в навыке `docs/skill/tg`.
- Значение из переменной окружения перекрывает базу: `tg settings set` может
  записать значение, которое не действует, пока переменная задана. Ответ
  команды должен это показывать.
