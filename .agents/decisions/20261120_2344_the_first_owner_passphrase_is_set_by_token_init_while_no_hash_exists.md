# Первую фразу владельца задаёт tg settings token init, пока хэша в базе нет

## Context

[Запись списков доступа](20261120_2242_access_settings_are_written_only_with_the_owner_passphrase_typed_on_a_terminal.md)
требует фразу владельца, но после переноса хэша в базе ещё нет. Кто-то должен
задать первую фразу. Владелец 2026-11-20 выбрал вариант A вопроса Q9 плана
`20261120_2242_settings_in_database`.

## Decision

- Первую фразу задаёт `tg settings token init` в терминале, без эха, дважды
  для сверки, не короче 12 символов. Команда работает онлайн и офлайн и только
  пока в `owner_secret` нет хэша; при хэше она отказывает.
- Пока хэша нет, запись любого `access.*` отказывает всем вызывающим. Перенос
  из `access.json` пишет списки без фразы: это единственный такой путь.
- Шаг деплоя: владелец выполняет `tg settings token init` сразу после установки
  нового бинарника.
- Смена фразы (`token change`) требует старую фразу; сброс (`token reset`)
  работает только при остановленном Daemon.

## Why

- Отвергнуто: фраза при переносе (вариант B). Перенос идёт при `daemon start`,
  которому терминал не нужен, а агент запускает его без человека.
- Отвергнуто: `init` только при остановленном Daemon (вариант C). Владельцу
  пришлось бы останавливать Daemon ради первой фразы, а окно уязвимости от
  этого не закрывается.

## Cost

- Между деплоем и `token init` агент с псевдотерминалом может задать фразу
  первым. Окно закрывает шаг деплоя; если владелец увидит отказ `token init`,
  он сбрасывает фразу при остановленном Daemon и задаёт свою.
