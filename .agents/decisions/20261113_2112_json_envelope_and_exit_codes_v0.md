# Ответ CLI это JSON-конверт, коды выхода версии 0 закреплены

## Context

Агент должен разбирать ответ без догадок и узнавать результат по коду выхода
([INTENT.md](../../INTENT.md)). Установленная `tg` отвечает конвертом
`{ok,data}`. Формат выдачи (JSON, JSONL, TOON) остаётся открытым вопросом, в
первом срезе нужен один.

## Decision

- Любая команда печатает в stdout одну строку JSON:
  `{"ok":true,"data":...}` или
  `{"ok":false,"error":{"code":"<имя>","message":"<текст>"}}`.
  Подсказки, запросы ввода и логи идут в stderr.
- Коды выхода версии 0, имена закреплены пакетом `exitcode`: `0 ok`,
  `1 failure`, `2 usage`, `3 daemon_not_running`, `4 not_authorized`,
  `5 telegram_error`, `6 flood_wait`. Значения не меняются, новые
  добавляются в конец.
- Ошибка RPC превращается в код выхода по её коду (`-32001` в 4, `-32002` в 5,
  `-32003` в 6, неверные параметры в 2, остальное в 1).
- Сообщение об ошибке никогда не содержит код входа, пароль, `api_hash`.

## Why

- Конверт знаком агентам по `tg`, ошибка и успех различаются полем `ok`.
- Имя кода в `error.code` читается и без таблицы, число в коде выхода
  пригодно для скриптов.
- Отвергнуто: ошибки в stderr, данные в stdout. Агенту пришлось бы читать два
  потока.
- Отвергнуто: JSONL или TOON в первом срезе. Формат не выбран, а один формат
  проще проверить.

## Cost

- Таблица кодов неполна: частичный успех пакетных команд, идемпотентность и
  самоописание добавит отдельный план.
- Ошибка дублируется: в конверте и в коде выхода, их нужно держать в
  соответствии (тест `TestCodesAreUniqueAndNamed` и тесты `internal/cli`).
