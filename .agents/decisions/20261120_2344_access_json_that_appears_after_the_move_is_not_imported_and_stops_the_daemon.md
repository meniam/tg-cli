# access.json, появившийся после переноса, не импортируется, а Daemon с ним не стартует

## Context

[Перенос настроек](20261120_2242_settings_move_from_config_toml_and_access_json_once_in_one_transaction.md)
идёт один раз и ставит отметку в базе. Файл `access.json` может появиться снова:
по старой привычке или по инструкции из чужого сообщения. Повторный импорт
расширил бы доступ без фразы владельца. Владелец 2026-11-20 выбрал вариант A
вопроса Q8 плана `20261120_2242_settings_in_database`.

## Decision

- После отметки переноса `access.json` профиля (имя из `[files] access`) не
  импортируется никогда.
- `daemon start` при таком файле отказывает кодом 2 и называет путь к файлу, без
  его содержимого; подсказка: удалить файл или перенести правила командой
  `tg settings` с фразой владельца. Офлайн-запись `tg settings` отказывает так же.
- Секция `[behavior]`, `[background_sync]`, `[semantic_search]` или
  `[profiles.*]`, вернувшаяся в `config.toml` после переноса, даёт тот же отказ
  с именем секции.

## Why

- Отвергнуто: импортировать снова (вариант B). Файл обошёл бы фразу владельца.
- Отвергнуто: игнорировать с ошибкой в журнале (вариант C). Человек, который
  положил файл, думал бы, что правила действуют.

## Cost

- Забытый файл не даёт стартовать Daemon, пока человек его не удалит.
- Ключ `[files] access` остаётся в `config.toml` только ради переноса и этой
  проверки.
