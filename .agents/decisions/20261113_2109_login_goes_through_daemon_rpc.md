# Вход в аккаунт идёт через Daemon по RPC

Decided: 2026-11-13
Revised: —

## Context

Вход по номеру телефона требует трёх шагов: номер, код из Telegram, пароль 2FA
(если он включён). Сессию Telegram может держать только один процесс: два
процесса на одной сессии дают `AuthKeyDuplicatedError`, и Telegram может её
разлогинить. В `gotd/td` вход построен на интерфейсе `auth.UserAuthenticator`,
который сам вызывает колбэки `Phone`, `Code` и `Password`.

## Decision

- Вход выполняет Daemon. CLI ведёт диалог с человеком и передаёт ответы по RPC.
- Методы: `auth.start {phone}`, `auth.code {code}`, `auth.password {password}`,
  `auth.cancel`. Каждый шаг возвращает `{state, user?}`, где `state` один из
  `code_required`, `password_required`, `authorized`.
- Daemon запускает `Login` в отдельной горутине. Колбэки `code` и `password`
  выставляют состояние и ждут ответа из канала. Одновременно идёт один вход,
  он живёт не дольше 5 минут.
- Неверный код завершает вход ошибкой Telegram, начинать нужно заново
  (`auth.start`).
- Код, пароль и номер не принимаются флагами и не попадают в логи: сервер RPC
  не пишет параметры запросов.

## Why

- Сессию владеет один процесс, Daemon: вход не создаёт второго клиента.
- `internal/cli` не импортирует `tgclient` (см. [структуру кода](20261113_2052_code_lives_in_cmd_and_internal.md)).
- Отвергнуто: отдельный процесс входа (`tg auth login`, как в установленной
  `tg`, где команда требует остановить Daemon). Нужен второй клиент на сессии
  и остановка Daemon, а `cli` обязан тянуть `tgclient`.
- Отвергнуто: код и пароль флагами. Они попадают в историю шелла и в `ps`.

## Cost

- В протоколе есть состояние входа и таймаут, их нужно тестировать (тесты в
  `internal/daemon`).
- Ошибка при вводе кода сбрасывает весь вход, повтор кода без нового
  `auth.start` невозможен.
- Неинтерактивный вход для агента (код из внешнего источника) не решён и
  остаётся в `FEATURES.md` пунктом 1.4.
