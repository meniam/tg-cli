# Базы данных лежат в db рядом с конфигом

## Context

База профиля `store.db` лежит в каталоге данных профиля
`~/Library/Application Support/tg-cli/<профиль>/` вместе с сессией, сокетом и
журналами. Конфиг лежит в `~/.config/tg-cli/config.toml`
([решение про config.toml](20261116_0017_config_toml_holds_paths_file_names_behavior_and_profile_settings.md)).
На этой машине `store.db` весит около 21 МБ, рядом лежат `store.db-wal` и
`store.db-shm`, пока работает Daemon.

## Decision

- База профиля лежит в `<каталог конфига>/db/<профиль>/<имя базы>`, по
  умолчанию `~/.config/tg-cli/db/default/store.db`. Имя файла по-прежнему
  задаёт ключ `[files] database`.
- Сессия, сокет, замок, журнал Daemon, журнал удалений и `access.json`
  остаются в каталоге данных профиля, которым управляет `home`.
- При старте Daemon старая `store.db` из каталога данных переносится в новое
  место автоматически: `wal_checkpoint(TRUNCATE)`, копия, сверка размера и
  `PRAGMA integrity_check`, затем удаление старого файла. Если новое место уже
  занято, а старый файл существует, Daemon не стартует (код 2).

## Why

- Так просил владелец: база рядом с конфигом, в подпапке `db`.
- Каталог на профиль, а не файл `db/<профиль>.db`, держит `-wal` и `-shm` рядом
  с базой и сохраняет смысл ключа `[files] database`.
- Отвергнуто: оставить базу в Application Support, пожелание владельца не
  выполнено.
- Отвергнуто: ручной перенос командой `tg db move`: до её запуска Daemon создал
  бы пустую базу.
- Отвергнуто: перенос только для новых профилей: два разных правила.

## Cost

- Данные профиля разнесены по двум папкам, а база в 21 МБ окажется в
  `~/.config`, который часто синхронизируют или кладут в dotfiles: каталог
  `db/` нужно исключить из такой синхронизации.
- Автоперенос трогает историю аккаунта: ошибка может её повредить, поэтому
  старый файл удаляется только после сверки, а перед первым запуском на живом
  профиле нужна резервная копия `store.db`.
- Решение меняет проверку смены имени файла и `ResolvePaths`.
