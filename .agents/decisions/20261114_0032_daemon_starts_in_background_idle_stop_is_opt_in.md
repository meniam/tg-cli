# Daemon уходит в фон по умолчанию, остановка по простою включается флагом

## Context

Сейчас `daemon start` занимает терминал, и агенту приходится держать его
отдельным процессом. В `FEATURES.md` пункт 2.7: Daemon останавливается сам при
простое. Следующий план про живой поток требует, чтобы Daemon работал
постоянно и копил обновления Telegram в базе, а остановка по простою с этим
конфликтует.

## Decision

- `daemon start` по умолчанию перезапускает программу отдельным процессом (в
  новой сессии, без терминала) с флагом `--foreground`, пишет журнал в
  `<каталог профиля>/daemon.log` (права 0600, без текстов сообщений и
  секретов), ждёт, пока сокет ответит на `ping` (не дольше 15 секунд), и
  печатает конверт с PID, сокетом и путём к журналу. Если процесс завершился
  раньше, команда печатает ошибку с последними строками журнала. `--foreground`
  сохраняет нынешнее поведение.
- `--idle-timeout ДЛИТЕЛЬНОСТЬ` включает остановку: если запросов нет дольше
  этого времени и нет запросов в работе, Daemon корректно завершается. Значение
  по умолчанию 0: остановки нет, Daemon живёт до `daemon stop` или до сбоя.
- Автозапуск Daemon при вызове другой команды по-прежнему не делаем (решение
  «явный `daemon start`» остаётся).

## Why

- Фоновый запуск нужен агенту; журнал нужен, чтобы видеть, почему фоновый
  процесс не стартовал.
- Остановка по умолчанию выключена, потому что живому потоку нужен постоянный
  процесс; кому нужна остановка, включает её явно.
- Отвергнуто: остановка через 30 минут по умолчанию. Конфликтует с живым
  потоком, пришлось бы менять умолчание позже.
- Отвергнуто: не делать остановку вообще. Пункт 2.7 остался бы невыполненным и
  не было бы способа ограничить время жизни.
- Отвергнуто: автозапуск. Скрывает процесс с доступом к аккаунту.

## Cost

- Забытый Daemon держит сессию и память (в простое мало, сокет доступен
  только владельцу).
- Фоновый процесс сложнее отлаживать: нужен файл журнала, который растёт; план
  включает простое ограничение размера.
- Только платформы с `setsid`; список платформ ещё не определён.
