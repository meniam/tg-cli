# Векторы живут в vectors.db, эмбеддинги bge-m3 считает Ollama, индекс фрагменты разговора, слияние RRF

## Context

Пункт FEATURES 13.1 («токенизированный и векторный поиск») ждал решения. На базе владельца (55 296 сообщений без удалённых и служебных, медиана сообщения короткая) обычный FTS5 не знает форм слов и смысла. Спайк 2026-11-20 на M1 Max: Ollama `bge-m3` (1024 измерения, 1,2 ГБ) считает около 5 000 токенов в секунду, в 6-11 раз быстрее чистого Go (`hugot`, `multilingual-e5-small`), у которого к тому же нет усечения длинного текста. Симуляция нарезки по правилам `brain-agent` на копии базы: 7 037 фрагментов, 6 382 от 200 символов покрывают 98,9% текста, около 1,5 млн токенов, векторы около 26 МБ.

## Decision

- Векторы лежат в отдельном `vectors.db` в каталоге профиля (SQLite, `modernc.org/sqlite`, своя `user_version`), не в `store.db`. Текста сообщений там нет: ключ `(chat_id, first_id)`, интервал, тема, модель, дайджест, размерность, `text_hash`, вектор float32.
- Поиск векторов полным перебором в Go за интерфейсом `vectorIndex`; `sqlite-vec` и zvec не берём.
- Эмбеддинги: Ollama по HTTP (`/api/embed`), модель `bge-m3`, веса в хранилище Ollama, не в бинарнике. Внешние API не используются.
- Единица индекса: фрагмент разговора (правила из `brain-agent`: пауза 30 минут при 300 набранных символах, потолок 1500 с перекрытием 200, ответ отменяет разрез, тишина 24 часа, предел 7 суток, индекс от 200 символов), плюс разрез по смене темы форума.
- Выдача: слияние RRF `k = 60`, вектор опционален, при сбое остаётся поиск по словам.
- Функция выключена по умолчанию: `[semantic_search] enabled = true` включает владелец.

## Why

- Ollama: скорость и качество многоязычной модели, бинарник остаётся чистым Go без нативных библиотек. Отвергнуто: `hugot` на чистом Go (медленно, нет усечения), `llama.cpp` и ONNX Runtime внутри процесса (нативные библиотеки), внешний API (переписка уходит наружу).
- Отдельный файл: векторы производные, их пересобирают без миграций, а крупная запись не конкурирует с записью сообщений в `store.db`.
- Перебор: 26 МБ векторов, десятки миллисекунд; `sqlite-vec` требует смены драйвера, zvec нативной библиотеки.
- Фрагменты: одиночные реплики слишком короткие, опыт `brain-agent` на 1387 сообщениях.

## Cost

- Нужен запущенный Ollama с моделью `bge-m3`; без него остаётся обычный поиск.
- Пороги нарезки взяты из другого корпуса, их проверяет эталонный набор владельца.
- Два файла данных вместо одного, нужна сверка (закрытый чат, удалённое сообщение).
- Условие пересмотра: десятки тысяч фрагментов и более, тогда замеры из плана показывают, нужен ли приближённый индекс.
