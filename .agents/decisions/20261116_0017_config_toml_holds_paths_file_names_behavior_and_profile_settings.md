# Пути, имена файлов, поведение и настройки профиля лежат в config.toml

## Context

Файла настроек нет. Путь данных задаёт переменная `TG_CLI_HOME`, поведение
задают `TG_CLI_PROXY`, `TG_CLI_THROTTLE_PERCENT`, `TG_CLI_FLOOD_AUTOWAIT`,
`TG_CLI_EXPECT_USER`, а настройки профиля лежат отдельными файлами `client`,
`device`, `transport`, `proxy` в каталоге профиля (`internal/daemon/paths.go`).
Имена файлов зашиты в код: `store.db`, `session.json`, `daemon.log`,
`deletions.jsonl`, `access.json`. Каталог данных по умолчанию
`~/Library/Application Support/tg-cli`; на этой машине в нём один профиль
`default`, база `store.db` около 21 МБ.

## Decision

- Конфиг: `~/.config/tg-cli/config.toml`, одно место на macOS и Linux. Он лежит
  отдельно от каталога данных, потому что сам задаёт путь к данным.
- Приоритет: флаг, переменная окружения, конфиг, значение по умолчанию.
- Имя каталога данных по умолчанию остаётся `tg-cli`. Путь меняется ключом
  `home` в конфиге.
- В конфиг уходят: `home`, `default_profile`; таблица `[files]` с именами
  файлов профиля (база, сессия, журнал, журнал удалений, `access.json`);
  `[behavior]` (`throttle_percent`, `flood_autowait`, `expect_user`);
  `[profiles.<имя>]` с `client`, `device`, `transport`, `proxy`.
- Файлы профиля `client`, `device`, `transport`, `proxy` заменяются конфигом.
  Миграция идёт автоматически в начале команд, читающих настройки профиля, и
  командой `tg config migrate`; есть ещё `tg config path` и `tg config show`.
  Перед переносом четыре файла и текущий `config.toml` копируются в
  `<home>/.config-migration-<время>/`. Затем команды, которые писали эти
  файлы, пишут в конфиг: правятся только строки нужного `[profiles.<имя>]`,
  комментарии сохраняются. Библиотека `pelletier/go-toml/v2`.
- Если имя файла `database`, `session` или `access` сменили после первого
  запуска и в каталоге остался файл со старым именем, Daemon не стартует и
  выходит с кодом 2; для журналов выдаётся предупреждение.
- Прокси с паролем пишется в конфиг с правами 0600, как сегодня в файл `proxy`.
- Ключи конфига видны в блоке `config` команды `tg schema`.
- Путь конфига ровно `~/.config/tg-cli/config.toml`: без `XDG_CONFIG_HOME` и
  без `TG_CLI_CONFIG`.
- Остаются прежними: `TG_API_ID` и `TG_API_HASH` (учётные данные),
  `daemon.sock` и `daemon.lock` (у сокета предел пути 103 байта, произвольное
  имя его легко нарушит).

## Why

- Один файл вместо пяти отдельных файлов профиля и набора переменных:
  настройки видны и правятся в одном месте.
- Конфиг вне каталога данных переживает перенос данных в другое место.
- Отвергнуто: оставить `TG_CLI_HOME` и `--home` как единственный способ. Это
  не настройка в конфиге, как просил владелец.
- Отвергнуто: конфиг в `Application Support/tg-cli`. Если вынести данные
  оттуда, в старой папке остался бы только конфиг.
- Отвергнуто: оставить файлы профиля запасным источником. Два источника
  истины, владелец выбрал полный переход.
- Отвергнуто: учётные данные в конфиге. Это ещё один секретный файл, см.
  [решение про окружение](20261113_2111_profile_layout_and_credentials_from_env.md).

## Cost

- Миграция трогает файлы профиля. Резервная копия берёт только переносимые
  файлы, а не весь каталог профиля: копия `session.json` стала бы вторым
  экземпляром секрета (риск `AuthKeyDuplicatedError`), а копия базы при
  работающем Daemon с WAL несогласована. `session.json` и `store.db`
  миграция не затрагивает, вход в Telegram не слетает.
- Добавляется зависимость `pelletier/go-toml/v2`, а запись только строк
  профиля стоит около 150 строк своего кода на `unstable` API.
- Проверка имён файлов на каждом старте Daemon стоит микросекунды и защищает
  от пустой базы и от открытого чтения всех чатов при потерянном
  `access.json`.
- Правится `AGENTS.md`: `config` добавляется в список импортов `internal/cli`.
- Смена имени файла базы после первого запуска создаёт новую пустую базу, а
  старую не подхватывает: нужна проверка или предупреждение.
- Меняются команды, которые писали файлы профиля, и документация `docs/cli/`.
- Решение пересматривает пункт старого решения про временное имя каталога
  `tg-cli`: имя остаётся, путь настраивается.
