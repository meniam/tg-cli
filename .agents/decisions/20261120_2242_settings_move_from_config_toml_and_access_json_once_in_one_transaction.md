# Настройки из config.toml и access.json переносятся в базу один раз, одной транзакцией

## Context

Настройки переезжают в базу профиля
([решение о хранении](20261120_2242_settings_live_in_the_profile_database_and_config_toml_keeps_only_what_finds_it.md)).
У владельца сейчас один профиль `default`, его `config.toml` и `access.json`
действуют на живом аккаунте. Ошибка переноса списков открывает закрытые чаты.

## Decision

- Перенос выполняется один раз. Значения секций `[behavior]`,
  `[background_sync]`, `[semantic_search]`, `[profiles.<имя>]` и всё содержимое
  `access.json` пишутся в базу профиля одной транзакцией.
- После записи значения читаются из базы и сверяются с исходными файлами.
- Только после сверки из `config.toml` удаляются перенесённые секции
  (остаются `home`, `default_profile`, `[files]`), а `access.json` удаляется.
- До изменения файлов `config.toml` и `access.json` копируются в
  `<home>/.config-migration-<время>/`.
- Некорректный файл: отказ без частичной записи, файлы остаются на месте,
  политика доступа закрыта (как при сломанном `access.json` сегодня).
- Повторный запуск, когда файлов нет, ничего не меняет.
- Откат на старый бинарник возможен только из этой копии. Перед деплоем
  делается копия каталога `db/<профиль>`.
- Перенос проверяется на копии боевой базы и боевых файлов; живых проверок на
  аккаунте нет.

## Why

- Так решил владелец: один источник истины после переноса.
- Отвергнуто: оставить файлы и читать их вместе с базой. Два источника дают
  расхождение политики доступа.
- Отвергнуто: переименовать `access.json` вместо удаления. Копия в
  `.config-migration-<время>` уже есть, второй экземпляр списков не нужен.
- Сверка перед удалением: ошибка записи не должна стоить правил доступа.

## Cost

- Старый бинарник после переноса видит пустые списки доступа (всё открыто,
  запись выключена) и умолчания настроек. Новая миграция схемы не даст ему
  открыть базу, но откат требует вернуть файлы из копии и базу из копии
  `db/<профиль>`.
- Копия `access.json` лежит в `.config-migration-<время>/`, пока человек её не
  удалит.
- Перенос нескольких профилей и судьба файла, появившегося заново после
  переноса, решаются в плане `20261120_2242_settings_in_database`.
