# Фоновая дозагрузка истории идёт по расписанию в окне 08:00-20:00, выключена по умолчанию, дата первого сообщения лежит колонкой

## Context

Решение 20261114_1353 разрешало грузить историю глубже только по явной команде `chat sync start`. После колонки `raw` старые сообщения (67 583 строки у владельца) хранят прежний JSON Daemon и получают новый формат только при повторном чтении. Массовый обход одной командой владелец отклонил: ограничения Telegram для пользовательского аккаунта не документированы, на живом аккаунте уже ловили `FLOOD_WAIT` на 8 секунд после десяти чтений за минуту.

## Decision

- Планировщик в Daemon (`internal/daemon/background_sync.go`), включается `[background_sync] enabled = true` в `config.toml`, по умолчанию выключен. Без включения Daemon не делает новых запросов к Telegram.
- Работает с 08:00 до 20:00 по местному времени машины Daemon. Пауза между запусками случайная, 40-180 минут, считается от конца прошлой загрузки; первый запуск после старта Daemon тоже через случайные 40-180 минут. На запуске берётся один чат с `complete = 0`, в 20:00 задача отменяется, на следующий день выбор идёт заново.
- Порядок выбора: чаты типа `user`; затем чаты из `folder_chats` с `kind` равным `pinned` или `include` (правила папок не вычисляются); затем остальные, включая боты. Внутри группы свежие по дате последнего сообщения первыми. Чат с ошибкой загрузки пропускается до следующего дня.
- Перед выбором снимок папок обновляется, если он старше 4 часов.
- Страницы грузит тот же `historySyncManager`: у фоновой задачи случайная пауза 2-8 секунд между страницами, поле `source` (`manual` или `background`) в `rpc.HistorySyncJob`. Ручной `chat sync start` отменяет фоновую задачу и идёт первым.
- Дата первого сообщения хранится колонкой `sync_state.first_message_date` (миграция 0010), записывается в транзакции, ставящей `complete = 1`.
- Планировщик только читает, идёт через общий дроссель аккаунта с фоновой меткой и уважает списки доступа.

## Why

- Расписание в рабочие часы и один чат за запуск держат нагрузку близкой к обычному клиенту; выключенность по умолчанию оставляет включение за владельцем.
- Колонка вместо вычисления из `messages`: представление `chats_overview` считает дату по строкам без `deleted_at`, и локальное удаление первого сообщения сдвинуло бы её.
- Отвергнуто: явные правила папок (нужно вычислять тип и состояние чата, больше граничных случаев).
- Отвергнуто: запуск планировщика сразу после старта Daemon (каждый перезапуск давал бы нагрузку).
- Отвергнуто: ручная загрузка ждёт фоновую (владелец ждал бы часами).

## Cost

- Миграция 0010 необратима для старых бинарников (`store.Open` отказывает на базе новее бинарника), перед деплоем нужна копия базы.
- Полный обход 245 чатов займёт недели: порядка пяти запусков в сутки, один чат за запуск.
- Рост базы: повторное чтение перезаписывает `raw` в новом формате.
- Состояние планировщика живёт в памяти, после перезапуска расписание строится заново.
