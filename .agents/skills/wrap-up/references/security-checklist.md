# Чеклист безопасности для wrap-up

Проходить по diff и неотслеживаемым файлам, а не по всему репозиторию. Цель — поймать
то, что внесла эта работа. Полный аудит — задача скилла `expert-security`; вызывать
его, когда diff большой или трогает auth, платежи или доступ к данным.

## Секреты

- В добавленных строках нет API-ключей, токенов, паролей, приватных ключей и строк
  подключения с учётными данными. Скан скрипта — отправная точка; также читать
  тестовые фикстуры, примерные конфиги, ноутбуки и документацию, где секреты
  прячутся под видом «примеров».
- Новые файлы — не `.env`, `credentials.json`, `*.pem`, JSON сервисного аккаунта,
  kubeconfig или история shell. Если такой файл нужен локально, он в `.gitignore`
  и у него есть пара `.env.example` с плейсхолдерами.
- Секрет, попавший в коммит в любой момент работы, даже удалённый потом,
  скомпрометирован. Ротировать и написать об этом в отчёте; удалить строку
  недостаточно.
- Добавленные логи и сообщения об ошибках не печатают токены, id сессий, полные тела
  запросов, персональные данные.
- Ничего чувствительного не перекочевало из разговора в файл: URL с токенами
  в query string, подписанные ссылки, секреты webhook'ов.

## Игнор-правила и артефакты

- `.gitignore` покрывает то, что появилось за работу: `.env*`, артефакты сборки,
  coverage, кэши, файлы редакторов, локальные базы, скачанные фикстуры.
- Ничего большого или бинарного не добавлено случайно (скриншоты, дампы, архивы).
- Lockfile закоммичен и согласован с манифестом.

## Зависимости

- Каждая новая зависимость — именно тот пакет, что имелся в виду: сверить точное имя
  с реестром, следить за typosquat'ами и похожими именами с дефисом или переставленной
  буквой.
- Версия зафиксирована lockfile. Никаких `latest`, никаких плавающих git-ссылок
  на ветку.
- Пакет поддерживается, лицензия совместима, и есть причина держать его в проекте.
  Зависимость, добавленная «попробовать» и больше не импортируемая, убирается.
- Post-install скрипты, если есть, понятны.
- Прогнать аудит экосистемы, когда это дёшево: `npm audit`, `pnpm audit`,
  `uv pip audit` или `pip-audit`, `cargo audit`, `govulncheck`. Новые high в отчёт;
  автофикс во время wrap-up только если это patch-бамп.

## Чувствительные места в diff

Читать каждое из них осознанно, если изменение их касается.

- Аутентификация и сессии: работа с паролями, время жизни токенов, флаги cookie
  (`HttpOnly`, `Secure`, `SameSite`), инвалидация при logout, remember-me.
- Авторизация: каждый новый endpoint или действие проверяет права вызывающего,
  доступ на уровне объекта (IDOR), admin-only пути, изоляция тенантов.
- Обработка ввода: SQL и query builders (параметры, не конкатенация), shell
  и subprocess (массив аргументов, без `shell=True`), пути к файлам из ввода (без
  traversal), десериализация (`pickle`, `yaml.load`, `unserialize`), regex
  на недоверенном вводе (катастрофический backtracking), XML (entity expansion).
- Обработка вывода: HTML-инъекции (`innerHTML`, `dangerouslySetInnerHTML`, шаблоны
  с выключенным autoescape), open redirect, заголовки из ввода.
- Загрузка файлов: лимиты типа и размера, хранение вне web root, генерируемые имена.
- Криптография: только стандартная библиотека или известные пакеты, никакого
  самодельного хэширования, никаких MD5 или SHA-1 для целей безопасности, random
  из CSPRNG.
- Сеть: проверка TLS включена, таймауты есть, исходящие URL не строятся из сырого
  пользовательского ввода (SSRF).
- Веб-платформа: CORS не `*` с credentials, CSP не ослаблен, CSRF-защита не снята
  с изменяющих состояние роутов, rate limit на auth и дорогих endpoint'ах.

## Конфигурация и инфраструктура

- Debug-флаги, verbose-логирование, открытый CORS, выключенная проверка TLS,
  тестовые учётки: ничего из этого не стало значением по умолчанию для production.
- Docker: секреты не запечены в слои, базовые образы не `latest`, если проект
  пиннит, процесс не запускается от root без причины.
- CI: секреты не выводятся в лог, новые шаги не запускают недоверенный код с write-
  токенами, сторонние actions зафиксированы по sha, если проект так делает.
- IaC (Terraform, Helm, Kubernetes): не добавлено wildcard IAM, публичных бакетов,
  открытых security groups.
- Миграции БД: обратимы или явно задокументированы как односторонние, новые view
  и права не раскрывают данные.

## Данные

- Реальные персональные данные не скопированы в тесты, фикстуры, документацию.
- Тестовые данные, созданные во внешних системах (строки, пользователи, загрузки),
  удалены или отмечены в отчёте.
- Новое логирование или аналитика не собирает больше, чем раньше, без решения.

## Отчёт

- Каждая находка с файлом и строкой, серьёзностью и тем, что сделано: исправлено,
  ротировано, отложено с follow-up.
- «Находок нет» означает, что чеклист применён и ничего не нашлось, а не что его
  пропустили. Пропущенные пункты перечислены как пропущенные.
