# Подписи и шрифт

Как пишем значения на экране и где моноширинный шрифт.

## Подписи значений

- Значение, которое стоит отдельно, пишем с заглавной: ячейка таблицы,
  бейдж `BadgeChoice`, пункт меню и фильтра, вариант `Select` и
  `ToggleGroup`, вкладка, чип `FilterChips`, значение `DescriptionList`.
  «Отгружен», «На складе», «Нет в наличии», «Есть / Нет».
- Внутри фразы значение пишем строчной, как часть предложения: справка,
  подсказка, описание, текст с числом («3 ждут отгрузки», «за всё время»).
- Словарь один, с заглавной. Фразу собирает код (`label.toLowerCase()` или
  своя форма для фразы), а не второй словарь со строчной.
- Почему так: отдельно стоящее значение читается как название состояния, а
  строчная в бейдже выглядит обрывком фразы; два словаря расходятся при
  первой правке.

## Числа в тексте

- Число согласуется со словом через `countOf` (`120 заказов`, `1 заказ`), а
  не «заказов: 120».
- Число в тексте — с разрядами: «12 345 товаров», а не «12345 товаров».
  `countOf` и `formatNumberText` разбивают их сами; `${n}` и `String(n)`
  для числа, которое может вырасти за тысячу, не пишем.

## Моноширинный шрифт

- По умолчанию моноширинный шрифт не используем ни для чего: ни для id,
  артикулов, путей, SQL и ошибок, ни в таблицах, ни в карточках и формах.
  `font-mono` в классах и проп `mono` у `Format*` не пишем.
- Ставим его, только когда пользователь прямо попросил, и только через кит:
  `FormatTextMono`, в гриде — `textMonoColumn()`.
- Исключение — код как разметка, а не данные: `CodeBlock`, `Kbd`, `code` и
  `pre` в справке, доках и markdown. Они моноширинные сами, классы им не
  дописываем и не убираем.

## Checklist

1. Отдельно стоящее значение с заглавной, внутри фразы — строчной.
2. Словарь значений один; строчную форму собирает код.
3. Число со словом — через `countOf`; в тексте число с разрядами, без
   `${n}` и `String(n)`.
4. `font-mono` и `mono` нет; моноширинный — только по просьбе и через
   `FormatTextMono` / `textMonoColumn()`.
