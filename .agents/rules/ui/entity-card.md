# Карточка сущности

Страница одной сущности: заказ, партнёр, товар, поставщик, сотрудник.
Собирает всё, что известно о сущности, в одном месте. Общие правила
страницы — в `page.md`, здесь только то, чем карточка отличается от списка.

## Заголовок: PageHeader

```tsx
<PageHeader
  breadcrumbs={[
    { href: '/', label: 'Главная', icon: House },
    { href: '/partners', label: 'Партнёры' },
  ]}
  icon={Handshake}
  title={partner.name}
  badges={<BadgeChoice value={partner.status} options={PARTNER_STATUS_OPTIONS} />}
  help={<HelpIcon id="partner" />}
/>
```

- **Крошки.** `breadcrumbs`, а не `back`: «Главная» домиком, дальше путь по
  меню до списка сущности. Раздел внутри группы меню получает и группу:
  `Каталог → Товары`. Саму карточку в крошки не пишем, она уже в `title`.
- **Знак сущности.** Слева от имени всегда что-то есть:
  - у сущности есть картинка (человек, логотип партнёра, фото товара) —
    `leading={<Avatar size="lg" />}`;
  - картинки нет или не загрузилась — `icon` сущности из словаря проекта
    (`icons.md`), та же, что в шапке списка и в меню. Пустое место вместо
    аватара не оставляем.
- **Имя.** `title` — имя сущности, никогда не пустое. Имени нет — серым
  «— без названия». Технический идентификатор (UUID, внешний id) в заголовок
  не выносим, он идёт в факты карточки.
- **Бейджи.** `badges` — состояние сущности одним-двумя бейджами:
  - статус из enum — `BadgeChoice` с тем же словарём, что в колонке списка:
    иконка, подпись и цвет совпадают;
  - отклонения от нормы (удалён в источнике, ошибка выгрузки) — бейджем,
    тоже через `BadgeChoice` или пресет. Норму («выгружен», «активен») не
    помечаем;
  - ссылки и кнопки в `badges` не кладём.
- **Справка.** `help={<HelpIcon id="…" />}` обязателен: статья о сущности,
  её статусах и полях.
- **Действия.** `actions` — только действие над сущностью целиком: открыть
  в источнике (учётная система, кабинет поставщика), история, удалить.
  Правка отдельных полей — в карточке с этими полями, не в шапке. Кнопки —
  иконкой с `tooltip` (`mode="utility"`).
- **Описание.** `description` у карточки обычно нет: факты идут плитками и
  `DescriptionList` под шапкой. Исключение — одна строка о происхождении
  данных («снимок из учётной системы получен вчера»).
- **Счётчик.** `count` у карточки не ставим: число чего-то внутри сущности —
  плитка или заголовок вкладки.

## Таблицы внутри карточки

Списки, связанные с сущностью (заказы партнёра, отгрузки заказа),
собираются как список раздела, но без растяжки на экран:

- `Card` + `CardMenubar` + `AgGrid`, правила панели и колонок те же
  (`menubar.md`, `tables.md`). `fill` не нужен.
- Высота: до ~20 строк — по строкам (`domLayout="autoHeight"`), длиннее —
  фиксированная высота с прокруткой внутри грида.
- Несколько списков — вкладки `Tabs mode="underline"` через `useTabState`,
  выбранная вкладка в адресе. Карточка сама уже во вкладке страницы —
  вложенной группе свой ключ: `useTabState(TABS, 'orders', { name: 'partner' })`
  → `partner.tab`. Свой `useQueryState` под вкладки не пишем.

## Чек-лист

1. `breadcrumbs` по пути меню, без самой карточки.
2. Слева от имени аватар или иконка сущности из словаря.
3. `title` не пустой и не технический id.
4. Статус — `BadgeChoice` тем же словарём, что в списке; норма не помечена;
   ссылок и кнопок в `badges` нет.
5. Есть `help`.
6. `actions` — только действия над сущностью целиком, иконками с `tooltip`.
7. `count` и длинного `description` у карточки нет.
8. Таблицы внутри — `Card` + `CardMenubar` + `AgGrid`, высота по строкам до
   ~20 строк.
9. Вложенные вкладки — `useTabState` со своим `name`.
